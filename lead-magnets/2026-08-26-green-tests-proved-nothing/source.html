Five Checks That Lie

Five green checkmarks. None of them proved what I thought they proved. I found all five in my own work, in one week. Not in someone else's.

Run these against your own status checks

In order. Each takes a few minutes and tells you honestly whether a green light means what you think it means.
01The bill only I could see

Looks likeA test is an automatic checkbox your code has to clear before it ships. This one kept passing. It was quietly making a real, billed call to a live vendor every single time it ran.

VerifyCut the live connection and run the test again. If it still passes, it was never actually testing your work.

Real passThe test runs against a stand-in for the vendor, not the live paid service. A separate, clearly labeled test covers the real connection.

02The link that goes nowhere

Looks likeA report said "done" and handed back a link. Nobody had opened it. The page behind it was empty.

VerifyOpen the link yourself. A link existing is not proof of what's on the other end.

Real passThe check confirms what's actually at the other end of the link, not just that a link got produced.

03The demo only the demo team could run

Looks likeEvery test passed inside the demo team's own setup. The moment someone ran it the way a real user would, outside that setup, it broke immediately.

VerifyHand it to someone outside the process. Watch them run it cold, in their own environment, not yours.

Real passThe test runs the way a real person actually encounters the thing, not inside a setup built just to make it pass.

04The test that cannot fail

Looks likeThe test data for a scanned-document tool was typed text, not an actual scan. Typed text is already machine-readable, so there was no way for that test to ever fail.

VerifyAsk one plain question: what would actually make this test fail? If you can't answer that, it isn't testing anything.

Real passThe test runs on the same messy, real-world input the tool was built for: an actual scan, not a clean stand-in.

05The fix that only fixed one copy

Looks likeA wrong number got corrected in one file and the ticket got closed. A second place that showed the same number, the one a customer actually saw, still had the old value.

VerifyCheck everywhere the value could show up to a real user, end to end, not just the one file someone happened to edit.

Real passThe value is correct wherever it's produced or displayed, not just wherever it happens to be stored.

"If a check has never failed, you have not verified that it works."
