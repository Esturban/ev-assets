A working checklist

Five Checks That Lie

Five passing checks that proved nothing, found in one person's own pipeline in 48 hours. Every one of them produced a real green signal. Each measured something adjacent to what was actually being cared about -- a passing test proves the code behaves the way the test invokes it, not that the program runs.

Run these against your own suite

In order. Each one takes minutes to check, and tells you honestly whether a green result means what you think it means.
01The billed-API mirage

Looks likeA suite that passes because it is quietly making real, billed calls to a live API -- it only fails in CI, where there is no key.

VerifyRun the suite with the API key unset. If it still passes, it was never testing your logic.

Real passThe suite runs against a mock or fixture, no key and no network required. A separate, clearly labeled integration test covers the live call.

02The URL that resolves to nothing

Looks likeA trace URL returns success and resolves to nothing. The check confirmed a URL came back, not that it pointed anywhere real.

VerifyTake the URL your check produced and actually open or fetch it.

Real passThe check asserts on the content the URL resolves to, not on the shape of the string.

03The import path only the test runner sees

Looks likeDemo scripts break with a ModuleNotFoundError while the suite stays green -- the test runner put the repo root on the import path, running the script directly does not.

VerifyRun every entry point the way a real user would, outside your test runner's environment.

Real passThe suite exercises the same import path your real entry points actually use.

04The test that cannot fail

Looks likeFixtures written in markdown for an OCR pipeline. Markdown is already machine-readable, so the test cannot fail -- which means it cannot pass either.

VerifyAsk one plain question: what would actually make this test fail? If you cannot describe it, the test is not testing anything.

Real passFixtures use the real input format the pipeline was built for -- an actual scanned image, not a transcription of what it says.

05The single-file grep close

Looks likeA task closed after grepping one file for the right constant, while a second render path still showed the old value.

VerifySearch every path that could touch the value, then check what a user actually sees, end to end -- not just what the source file now says.

Real passThe value shows correctly wherever it is produced or rendered, not just wherever it happens to be stored.

"If a check has never failed, you have not verified that it works."
